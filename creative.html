Can a browser reaction game give useful practice feedback?

Flash Tap is a proposed practice tool for students who want a short, repeatable exercise and a private record of their own progress.

Two concepts

A reaction game gives immediate feedback and a numeric result. Its main risk is that timing varies with input devices and browser conditions. A study-session tracker would record time spent on a subject and chart weekly totals. Its main risk is that elapsed time gives limited information about whether a session was useful.

The plan selects the reaction game. Each practice attempt provides a clear interaction and a result that can be checked in the browser. The existing local Flash Tap prototype provides a reference for the wait, cue, and false-start states.

Evidence and assumptions

  • Evidence. The browser’s Performance API exposes elapsed milliseconds from a monotonic clock. Use it to measure the interval between the ready cue and the input in one browser session. MDN Performance.now(), checked November 11, 2026
  • Evidence. Flask documents cookie flags and protections for state-changing requests. Configure secure session cookies in deployment and use CSRF tokens for writes. Pallets Flask web security, checked November 11, 2026
  • Interpretation. Display a personal practice history and label results as browser measurements. Client-side timings can be altered, and device differences limit comparisons between players.
  • Assumption. Users will understand a visible cue with both text and color. Test the cue with keyboard and pointer input during the first working slice.

Five user stories

  1. As a student, I can register and sign in so I can return to my practice history.
  2. As a player, I can start a round and respond to a randomized cue with a key or click. An early input shows a false-start message.
  3. As a player, I can save a completed attempt once so my result survives a reload.
  4. As a returning player, I can see my latest attempts and recent median in a private dashboard.
  5. As an account owner, I can update my display name after signing in.

Architecture and checks

Browser cue and input → Flask routes and session checks → SQLite users and attempts → private dashboard

Use Python 3.12, Flask, Jinja, SQLite, vanilla JavaScript, pytest and Playwright. Hash passwords with Werkzeug. Derive record ownership from the session on the server. Validate submitted timings, reject invalid or already-used round IDs, and enforce uniqueness in SQLite.

Planned experiment. Compare latest-result feedback with a median of five recent attempts. Ask a peer to interpret both displays using the same example data and note which display helps them explain what changed.

Planned checks. Exercise false starts and completed rounds, reload to check persistence, retry a duplicate save, and attempt to read another account’s records. Compare a simple round state function with separate state objects using the same transition tests before choosing the implementation.
